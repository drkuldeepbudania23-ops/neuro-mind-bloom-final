# Automatic WhatsApp & email notifications

Everything here is **optional**. Until the keys below are added, the site works exactly as before
and the doctor keeps using the manual "Open WhatsApp / Email" buttons. Each channel is "skipped"
when it is not configured — nothing breaks.

## What is sent, and when

| Event | To | Trigger | WhatsApp template | Email |
|---|---|---|---|---|
| Booking received | Patient | Booking form saved (`/api/notify/booking`, once per booking) | `nmb_booking_received` | ✅ |
| New booking alert | Doctor (`DOCTOR_ALERT_*`) | same | `nmb_new_booking_alert` (English) | ✅ |
| Appointment confirmed | Patient | Doctor clicks **Confirm** in Appointments | `nmb_appointment_confirmed` | ✅ |
| Appointment rescheduled | Patient | Doctor changes date/time in Appointments → **Save & notify** | `nmb_appointment_rescheduled` | ✅ |
| Payment QR / link | Patient | Doctor clicks **Auto-send (WhatsApp + Email)** in "Send Payment QR" | `nmb_payment_request` | ✅ |
| Payment received | Patient | Razorpay payment verified (once) | `nmb_payment_received` | ✅ |
| E-prescription | Patient | Prescription → **Email** (server email with PDF attached); API also supports WhatsApp | `nmb_prescription_ready` (PDF as document) | ✅ PDF attached |
| Follow-up reminder | Patient | Daily 9:00 AM IST cron, for follow-ups whose **Reminder date** is tomorrow | `nmb_followup_reminder` | ✅ |

The **WhatsApp button** on the prescription page still opens the doctor's own WhatsApp chat with
the patient — now the message contains a **secure PDF download link** (valid 3 days; resend from Patients → history for a fresh link) instead of
"please attach the PDF".

## Secure prescription link

`/api/rx/<token>` — the token is HMAC-signed with `RX_LINK_SECRET` and expires after 3 days. Only
**e-signed** prescriptions saved to the cloud can be downloaded. The PDF is generated on the server
(A4, single page when it fits, numbered medicines, registration no., optional TELECONSULTATION
label, e-signature, footer "Not valid for medicolegal purpose."). Links are `no-store` and `noindex`.

> The signature image is no longer in `/public` (it was downloadable by anyone). It is embedded in
> server-only code (`lib/server/rxAssets.ts`, generated by `scripts/embed-rx-assets.py`).

## 1. Email — Resend (simplest, free tier available)

1. Create an account at resend.com → **Domains** → add `neuromindbloom.com` → add the DNS records it
   shows (at your domain registrar). Wait for "Verified".
2. **API Keys** → create a key → put it in Vercel as `RESEND_API_KEY`.
3. `EMAIL_FROM="Neuro Mind Bloom <care@neuromindbloom.com>"`, `EMAIL_REPLY_TO=drkuldeepbudania23@gmail.com`.

## 2. WhatsApp — Meta WhatsApp Cloud API

Needs a WhatsApp Business account in Meta Business Manager and a phone number registered to the
Cloud API. **A number that is registered on the Cloud API cannot be used in the normal WhatsApp /
WhatsApp Business phone app at the same time** — so use a separate number for automation, or keep
+91 93763 15331 in the app and use another number here.

1. developers.facebook.com → create an app (type *Business*) → add **WhatsApp**.
2. Add & verify the phone number → copy the **Phone number ID** → `WHATSAPP_PHONE_NUMBER_ID`.
3. Create a **System User** with a permanent token (`whatsapp_business_messaging` permission) →
   `WHATSAPP_TOKEN`.
4. Create the message templates below (category **Utility**), in **English (en)** and **Hindi (hi)**
   (except the doctor alert: English only). Template names and the order of `{{n}}` must match exactly.
5. Meta charges per conversation (utility rates in India are low); check current pricing in Meta.

## 3. Follow-up reminders (Vercel Cron)

`vercel.json` runs `/api/cron/followup-reminders` daily at 03:30 UTC (9:00 AM IST). Set
`CRON_SECRET` (32+ random characters) in Vercel — Vercel sends it automatically as
`Authorization: Bearer …`. In **Follow-up**, fill the new **Reminder date** (and email, optional).
Each follow-up is reminded only once.

## Environment variables

See `.env.example`: `RX_LINK_SECRET`, `PUBLIC_BASE_URL`, `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`,
`RESEND_API_KEY`, `EMAIL_FROM`, `EMAIL_REPLY_TO`, `DOCTOR_ALERT_WHATSAPP`, `DOCTOR_ALERT_EMAIL`,
`CRON_SECRET`. All are **server-only** (no `NEXT_PUBLIC_` prefix) and never reach the browser.

## Testing on the development project

Use the separate dev Firebase project. For WhatsApp, Meta gives a free **test number** that can
message up to 5 verified recipient numbers — ideal for testing before go-live.
